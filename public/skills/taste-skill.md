# Taste Skill
**Author:** Leonxlnx
**Domain:** Craft & Taste
**Purpose:** Senior UI/UX frontend skill enforcing anti-slop design decisions, motion quality, and architecture discipline. A "no mediocre output" enforcement layer.

## What It Does
Evaluates every design and frontend decision against a high-craft bar. Flags generic patterns, purposeless animations, and architectural shortcuts. Pushes output from acceptable to considered.

## Input Requirements
- UI component, screen, or codebase to review
- Current implementation (code or screenshots)
- Target quality bar or reference
- Optional: brand guidelines or design system

## Output
- Anti-slop design findings
- Motion quality flags
- Architecture improvement recommendations
- Quality verdict with priority list

## Quality Criteria
Every decision must be defensible. Generic = flagged. Motion without purpose = removed. Architecture shortcuts = documented risk.

## Edge Cases
- AI-generated UI that looks correct but feels generic
- Over-animated interfaces where motion distracts
- Visually complex designs that collapse on mobile
- Components that work in isolation but fail in context
- Designs that pass linting but fail taste

## Best Practices
- Prioritise eliminating mediocre patterns before adding new features
- Every decision must be defensible — "it looks better" is not enough
- Check motion at reduced speed before final approval
- Validate across breakpoints before considering work complete
- Reference great work explicitly — taste is trained, not assumed
