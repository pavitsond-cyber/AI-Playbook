# Impeccable
**Author:** pbakaus
**Domain:** Craft & Taste
**Purpose:** Flagship skill for production-grade, anti-generic frontend. The reference point for what "done" looks like at a high bar.

## What It Does
Sets and enforces the production standard for frontend work. Identifies every shortcut, generic pattern, and unfinished detail that prevents work from being considered truly complete.

## Input Requirements
- UI component or page to evaluate
- Current implementation (code or visual)
- Design intent and user goal

## Output
- Quality assessment with specific findings
- Generic pattern flags with replacements
- Polish recommendations with rationale
- Production readiness checklist

## Quality Criteria
No placeholder states. No generic animations. No unfinished edge cases. Every pixel intentional. Every interaction considered.

## Edge Cases
- Technically correct but visually generic output
- Components that look finished but lack empty/error states
- Designs that pass review but fail at real content lengths
- Interactions that work with mouse but break on touch
- Dark mode variants that were never fully specified

## Best Practices
- Define what "done" means before starting — impeccable is a standard, not a feeling
- Empty, loading, and error states are part of done — not optional polish
- Test with real content, not placeholder text
- Validate keyboard and touch interactions before calling complete
- Review from the user's perspective, not the developer's
